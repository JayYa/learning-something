# 掌握第 0 阶段第 1 课：类型擦除与双管道审阅模型

用户已理解 TypeScript 类型只在编译期存在、运行前会被擦除的底层机制，区分了只做剥离/转译的执行管道（`node`、Vite、esbuild、`tsx`）与全项目静态检查管道（`tsc --noEmit`），并掌握了 `tsc` 默认出错仍输出 `.js` 但返回非零退出码的行为，以及外部数据边界（如 `JSON.parse() as T`、`res.json()`）与 C# 运行时反序列化的核心差异。

**Evidence**: 完成课程 [0001 · 类型只活在编译期](../lessons/0001-types-vanish-at-runtime.html)，6 道检索自测题全部答对（6/6，2026-11-24）。

**Implications**: 已建立"先查门禁、再查运行时边界、警惕静默错算"的审阅直觉。第 0 阶段接下来可以推进到第 2 课（编辑器悬停与语言服务 `tsserver`），随后进入第 0 阶段审查练习或 0.5 阶段 JS 速通；后续课程不再重复解释类型擦除本身，改为通过课前热身题做间隔复习。
