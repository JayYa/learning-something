类型只活在编译期

学完这课你会知道：一段 TS 代码"能跑"，不代表它"类型正确"。审查 AI 写的项目时，要先问的就是这一点。

一个 5 分钟的实验

你本机的 Node 是 v26，可以直接运行 .ts 文件。找一个空目录，跟着做：

  1. 新建 hello.ts，内容如下。注意最后一行故意把字符串 "1" 传给了要求 number 的参数： 
    function add(a: number, b: number): number {
  return a + b;
}

console.log(add(1, 2));
console.log(add("1", 2));
  2. 运行之前，先在纸上写下你的预测：node hello.ts 会报错，还是会打印结果？如果打印，打印什么？
    然后运行： 
    node hello.ts
  3. 再用 TypeScript 编译器检查一次（第一次运行会自动下载 typescript 包）： 
    npx -p typescript tsc --noEmit hello.ts

我在你这台机器上跑过，结果是：

> node hello.ts
3
12

> npx -p typescript tsc --noEmit hello.ts
hello.ts(6,17): error TS2345: Argument of type 'string' is not
assignable to parameter of type 'number'.

同一个文件，Node 照常运行，还算出了一个错误的结果 12；tsc 则指出第 6 行有类型错误。

为什么会这样

Node 只删除类型，不检查类型。Node 运行 .ts 文件时，会把类型注解替换成空白，剩下的就是普通 JavaScript，然后直接执行。官方文档原话是 "no type checking is performed"。[Node.js 文档]

做类型检查的只有 tsc（以及编辑器里的 TS 语言服务）。而且就算 tsc 发现了错误，默认也照样输出 .js 文件，只是退出码不为 0。想让它出错时不输出，要专门打开 noEmitOnError 选项。[TSConfig: noEmitOnError] 这是 TS 团队有意的设计。[TypeScript #7602]

结果 12 是 JavaScript 的规则。+ 的两边只要有一个是字符串，就会做字符串拼接。[MDN: 加法] 类型被删掉以后，运行时只剩下 JS 的语义。

在 C# 里，类型错误就是编译错误，没有程序集，程序就跑不起来。类型在运行时也一直存在，可以用 typeof(T)、GetType() 做反射。

TS 不一样：类型检查和运行是两条互不相干的路，运行时也没有任何类型信息。官方的 C# 对照文档专门提醒过这一点。[Handbook: Rethinking Types]

这对审查 AI 代码意味着什么

AI 告诉你"代码跑通了"，只能说明 JS 语义下没崩，不能说明类型正确。所以接手一个 AI 写的项目，第一个问题是：类型检查在哪一步运行？打开 package.json，看 scripts 里有没有类似 tsc --noEmit 的命令，以及 CI 会不会执行它。如果哪里都没有，项目里的类型就只是"注释"，没有任何东西在把关。

检验一下

每题只能选一次。凭记忆作答，不要往上翻。

本机执行 node hello.ts，而 hello.ts 里有类型错误，会发生什么？

  1. 拒绝运行，打印类型错误
  2. 照常运行，不做类型检查
  3. 打印警告，然后继续运行
  4. 自动修正类型，然后运行
Node 只删除类型注解、不做检查，所以代码照常执行，按 JS 语义产生结果。

默认配置下，tsc hello.ts 发现了类型错误。结果是？

  1. 不会产出 JS，退出码为 0
  2. 照样产出 JS，退出码为 0
  3. 照样产出 JS，退出码非 0
  4. 不会产出 JS，退出码非 0
默认仍然输出 .js，但退出码非 0，CI 可以据此判定失败。打开 noEmitOnError 后才会不输出。

写一个泛型函数 function f<T>(x: T)。在函数体里，能像 C# 的 typeof(T) 那样拿到 T 是什么类型吗？

  1. 不能，T 在运行时已被擦除
  2. 可以，写法与 C# 完全相同
  3. 可以，但需要先开启反射
  4. 不能，泛型函数无法编译
类型（包括泛型参数）在编译后全部消失，运行时没有 T 可查。要在运行时判断，只能检查值本身，这是第 2 阶段"收窄"要讲的内容。

AI 交给你一个项目，package.json 的 scripts 里只有 "start": "node src/index.ts"。你最该追问哪一点？

  1. Node 版本是不是最新的
  2. 为什么不直接写成 JS
  3. 代码格式化是否统一了
  4. 类型检查到底在哪里跑
node 不做类型检查。如果 scripts 和 CI 里都没有 tsc，类型错误永远不会被发现。
