C# → TypeScript 速查

每学完一课，就往这里补几行：C# 直觉在哪里还管用，在哪里会失效，以及对应的审阅检查点。

类型与运行时

话题C#TypeScript出处
类型存在于编译期和运行时（CLR 元数据，可反射）只在编译期，运行前全部擦除，零运行时开销0001
检查与产出强耦合：类型错误则编译失败、无程序集解耦：tsc 出错默认仍产出 JS（退出码非 0）；Vite / Node 只剥离不检查0001
类型是否影响运行逻辑会（方法重载、default(T)、反序列化映射）绝不会（设计非目标：type-directed emit 被明确禁止）0001
两套"类型"统一的一套类型系统两套分离：TS 静态类型（贴在变量上，会被擦除）≠ JS 运行时类型（贴在值上）0001
运行时语义由 .NET / CLR 决定100% 是 JavaScript 规则（例如 "1" + 2 静默算出 "12"）0001
typeof(T) 与泛型泛型在运行时实体化，可反射读取 TT 运行时不存在；想校验结构需显式传校验函数或 schema0001
外部数据反序列化JsonSerializer.Deserialize<T> 按元数据校验构造JSON.parse(s) as T / res.json() 零运行时校验，脏数据直接流入0001
IDE 悬停与类型变化变量声明后类型固定，悬停主要确认具名类与成员位置敏感：同一变量在不同 if 分支里会被控制流收窄成不同类型，悬停查的是当前光标处的推导结果0002
IDE 与编译器版本Visual Studio 的 Roslyn 与本地 .NET SDK 绑定较紧VS Code 默认用内置 TS，可能与仓库 node_modules/typescript 版本不一致，需切换为 Use Workspace Version0002
嵌套类型报错阅读单行或扁平的编译错误，通常从头读起结构检查逐层缩进展开，最具体的错误原因落在最后一行，应自底向上阅读0002
空值表示只有 null（值类型用 T?）并存 undefined（引擎默认的缺失/未赋值）与 null（主动清空）；JSON.stringify 会丢弃 undefined 键但保留 null；typeof null === "object"0003
条件判断与真假值if (...) 编译期强制要求 bool任意值走 ToBoolean：8 个假值（false、0、-0、0n、""、null、undefined、NaN）；[] 和 {} 都是真值0003
逻辑运算与默认值&& / || 只返回 bool；默认值用 ??，空条件用 ?.&& / || / ?? 返回操作数本身；|| 会把 0、""、false 覆盖掉，设默认值认准 ??；可选链支持 a?.b、a?.[k]、fn?.()0003
相等比较与 NaN== 受强类型约束；double.IsNaN 明确无隐式转换一律优先 === / !==；== 会跨类型隐式转换（0 == "" 为真）；NaN !== NaN，拒绝全局 isNaN，改用 Number.isNaN / Number.isFinite0003
对象浅拷贝与覆盖record 的 with 表达式和 MemberwiseClone() 为浅拷贝{ ...a, ...b } 同样是浅拷贝（嵌套引用共享），靠后属性覆盖靠前属性；深拷贝用 structuredClone0004
解构与默认值元组/record 按位置解构，无属性名重命名解构对象解构按属性名（{ id: userId } 是重命名而非类型注解）；解构默认值只认 undefined，遇到 null 不生效0004
集合链式操作LINQ（Select / Where / OrderBy）延迟求值且不改原集合map / filter / reduce 急切求值（每步分配新数组）；sort / reverse / splice 会原地修改原数组，安全替代为 toSorted / toReversed / toSpliced0004

AI 代码审阅清单

  • 先查门禁：package.json 的 scripts 和 CI 里有没有跑 tsc --noEmit？build 是不是只跑了 vite build 而跳过了类型检查？（0001）
  • 再查边界：凡是 JSON.parse、fetch().then(r => r.json())、process.env、读文件等外部输入，有没有运行时校验，还是直接用了 as T / 类型注解"假装安全"？（0001）
  • 警惕静默错算：AI 说"跑通了 / 测试过了"时，确认是否验证过静态类型检查零报错，防止隐式转换导致静默数据污染。（0001）
  • 校准审阅工具：打开仓库先看 VS Code 状态栏是否启用 Use Workspace Version，切分支或装依赖后提示异常就跑 TypeScript: Restart TS Server。（0002）
  • 顺流悬停查 any：对未写注解的 AI 代码，顺着数据流悬停入口返回值和中间变量，防止 res.json() / JSON.parse() 返回的 any 无声扩散。（0002）
  • 自底向上读报错：遇到多行嵌套类型报错先看最后一行定位具体属性冲突，拒绝 AI 为省事加 as any 消音。（0002）
  • 默认值用 ?? 防误杀：扫到 a || fallback 时先问 0、""、false 是否合法；判断数组非空用 arr.length > 0 而非 if (arr)。（0003）
  • 判等与数值边界：默认一律 === / !==；对象防御检查补 x !== null；检测非法数值用 Number.isNaN 或 Number.isFinite，不用全局 isNaN 或 x === NaN。（0003）
  • 区分 null 与 undefined 序列化：更新接口里需要显式清空的字段必须传 null，避免传 undefined 被 JSON.stringify 静默丢弃。（0003）
  • 防浅拷贝污染与覆盖反序：扫到 { ...obj } 检查嵌套写入是否会改坏常量或入参，核对 { ...defaults, ...override } 顺序，留意解构默认值对 null 不生效。（0004）
  • 拦截数组原地修改与字典排序：入参数组上的 sort / reverse / splice 改为 toSorted / toReversed / toSpliced；数字排序必须显式提供比较器 (a, b) => a - b。（0004）
  • 盯紧 map 过滤与 reduce 初始值：不要在 map 里用 if 漏掉 else 混入 undefined；reduce 必传初始值防空数组抛错，避免在累加器里反复 { ...acc }。（0004）
