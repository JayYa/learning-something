TypeScript：做 AI 代码的审阅者

以 Matt Pocock《TypeScript Pro Essentials》的 17 个章节为骨架，按"读懂 → 挑错 → 提意见"重排为 7 个阶段。

设计思路

原课程面向"要自己写 TS 的 JS 开发者"，顺序按语言特性展开。你的目标不同：读懂并审阅 AI 写的代码。所以重排的原则有三条：

  1. 先学出现频率最高的。AI 代码里最常见的是基础注解、对象类型、联合类型，这些排在前面。
  2. 把"红旗"单独成阶段。any、as、!、过宽的类型，是 AI 最常用来"让报错消失"的手段，也是你最该会挑的毛病。原课程把它们分散在后面几章，这里提前到第 3 阶段。
  3. 借用 C# 经验，但盯住差异。类、接口、泛型、async 你在 C# 里都用过，这些快速过。真正要花时间的是 C# 直觉会出错的地方：类型在运行时会被擦除；类型兼容看结构，不看名字；类型错误默认不会阻止产出代码。每课都有一个"C# 对照"框。

你 JS 不熟，所以第 0 阶段之后插入一个短的 0.5 阶段：JS 速通。TS 的运行时行为完全是 JS 的，读 AI 代码时很多困惑其实来自 JS 而不是 TS。

每个阶段结束时有一次审查练习：我给你一段"AI 风格"的代码，里面埋了问题，你来写审查意见。这是这条路线和普通教程最大的不同。
